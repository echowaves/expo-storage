## Intent

**Problem:** The library tracks Expo SDK 57 (`expo` 57.0.9, `expo-file-system` 57.0.2) and its peer ceilings stop at `<58.0.0`, so an app on the released Expo SDK 58 hits a peer dependency conflict when it installs `expo-storage`. The rest of the dev tree has drifted behind as well.

**Approach:** Move the Expo toolchain to the SDK 58 pins, widen the peer ceilings so SDK 58 resolves, bump the package major to `58.0.0` (the version tracks the SDK major), and raise the remaining devDependencies to the newest versions compatible with the pinned lint/TS toolchain. No source or public API change is expected: SDK 58 keeps every `File` / `Paths` / `Directory` member this library uses.

</frozen-after-approval>

**Peer ranges:** `expo` and `expo-file-system` ceilings widen `>=53.0.0 <58.0.0` → `>=53.0.0 <59.0.0`. Floors stay put — the published intent is broad SDK support, and narrowing it would strand SDK 53–56 consumers for no gain. The `react` (`>=16.8.0 <20.0.0`) and `react-native` (`>=0.60.0 <1.0.0`) ranges already cover 19.3.0 and 0.88.1, so they are left alone.

**API evidence for "no source change":** from the `expo-file-system@58.0.13` tarball types — `Paths.document: Directory`; `new File(...uris: (string | File | Directory)[])`; `write(content, options?): Promise<void>`; `text(): Promise<string>`; `delete(): void`; `exists: boolean`; `get name()`; `get uri(): string`; `Directory.list(): (PublicDirectory | PublicFile)[]`; `Directory.create(options?)`. Every member used by `src/index.ts` and `src/consts.ts` is present with a compatible signature, and the 58.x changelog entries are additive (`File.preview`, permission-check fixes) or native-side. `await` on the now-synchronous `list()` return stays valid.

**Docs:** `README.md` requirements still claim "Expo SDK 54 or newer" / "expo-file-system 19.0.0 or newer", which contradicts the declared peers; align them with `>=53 <59` and name SDK 58 as the tested release.

**Not touching:** `src/`, `tsconfig.json`, `lib/` (generated), `.github/instructions/`, and the just-removed OpenSpec surface.

### Implementation record (2026-10-28)

Files changed: `package.json` (version, every devDependency pinned exact and raised where planned, peer ceilings `<58.0.0` → `<59.0.0`), `README.md` (Requirements section rewritten to the declared peer ranges plus the SDK-major/version note), `package-lock.json` (regenerated by `npm install`). `src/` needed no edit — the plan's API evidence held: `tsc` compiled `src/index.ts` and `src/consts.ts` against `expo-file-system@58.0.13` with no errors, including `await storageDir.list()` against the synchronous `(PublicDirectory | PublicFile)[]` return and the `instanceof File` filter.

Decisions: jest went to 30.5.2 and stayed — it runs green. Babel stayed on the 7.x line at 7.29.7 (latest 7.x) because `babel-jest@30` peers `@babel/core ^7.11.0`, so Babel 8 would break the jest transform for no benefit. `react` went to the SDK 58 pin 19.3.0 rather than registry-latest 19.3.1, since Expo's `bundledNativeModules.json` pins exactly 19.3.0 and mixing patch levels of react/react-native across the SDK boundary is how type conflicts appear downstream. TypeScript and the eslint/ts-standard family were left at their current versions per the `AGENTS.md` toolchain rule.

Environment notes (not repo defects, both reproduce on the pre-change baseline): `npm run lint` writes its cache to `~/.cache/ts-standard`, which this sandbox denies — it passes clean when `HOME` points somewhere writable (`HOME=$TMPDIR/lint-home npx ts-standard` → exit 0, no findings). `npm test` crashes in Watchman's state file, also denied — jest passes with `--watchman=false` (`No tests found, exiting with code 0`, expected under `--passWithNoTests`; the repo has no test files).

Correction to the record found in review: this plan's rationale for keeping the `>=53` peer floor was wrong. `expo-file-system` has no 53.x or 54.x releases at all (19.x is followed by 55.0.0), and SDK 53 / 54 pin `~18.1.11` / `~19.0.24`, so that floor already excludes SDK 53/54; the effective support floor is SDK 55. The ceiling widening stands, the README now states the real floor, and narrowing the manifest floor is recorded in `deferred-work.md`. Also: `npm install` did not error, but `npm ls --all` does report an invalid TypeScript peer from Expo's Metro-side `2g` package — see the deferred entry; the verification line below should be read as "install succeeds", which is what it was checked against.
